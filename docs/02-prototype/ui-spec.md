## 1. デザイン言語

コンセプト: 「暗室（ダークルーム）のカラーグレーディング卓」。写真の現像工程（現像・停止・色素浴・定着）になぞらえ、調整グループごとに固有色のインジケーターを持たせる。単一のアクセントカラーだけで彩る一般的な配色ではなく、機能グループと色を一対一で結びつけることで、スクロールが長い調整パネルでも今どの分類を見ているかが一目でわかるようにする。

- **背景**: 暖色寄りのほぼ黒（例: `#0e0d0b`）。色の判断を狂わせないよう、プロの色校正卓の定石に倣う。
- **グループカラー**（調整パネルの4グループに対応する識別色。グループ見出し横のドット、関連するアクティブ状態の強調色として使う）:
  - 明るさ系 = 現像（develop）= 暖色系アンバー
  - 色系 = 色素浴（dye）= マゼンタ〜紫
  - 質感・効果系 = 停止液（stop）= シアン〜青緑（「上級」タグの色もこれを流用）
  - 変形・仕上げ系 = 定着（fix）= インディゴ〜青
- **主要アクション色**: 一括適用ボタンは「現像」のアンバーで塗りつぶし、壁紙設定ボタンは「定着」のインディゴで縁取りのみ（塗りつぶさない）にして役割の違い（加工の実行 vs 最終確定）を色でも区別する。
- **数値表示**: スライダーの現在値はモノスペースフォントで、小さな読み取り機（LCD）風の背景チップに入れて表示する。単位（%, °, px等）も含めて等幅表示にする。
- **タイポグラフィ**: 日本語UI文言は読みやすさを優先しシステムのゴシック体を用いる。見出し（グループ見出し・パネル見出し）は太字・広めのレタースペーシング・大文字（英語部分）で、機器のラベルのような硬質な印象にする。数値・ファイル名・コード的な要素はモノスペースフォントで統一する。
- **パネル**: 角丸は最小限（3〜4px程度）にとどめ、丸みの強いカード風ではなく計器盤・ラック機材のような質感にする。枠線は1pxの細線。

この配色・書体のトークン（具体的な色コード等）は `prototype/index.html` の `:root` 変数を参照すること。本実装のUIフレームワーク（Tkinter）でどこまで再現するかは `/design` で判断してよいが、**4グループ＝4色の対応関係と、数値の等幅表示は踏襲する**。

## 2. 全体レイアウト

左: 対象画像一覧、中央: プレビュー（上部にBefore/After比較トグル）、右: 調整パネル（スクロール可能・4グループ）の3カラム構成。**右の調整パネルはウィンドウの上端から下端までフルハイトで配置する。** 一括適用・壁紙設定・出力設定のアクションバーは、右の調整パネルの下まで回り込ませず、**左（対象画像一覧）＋中央（プレビュー）の下にのみ配置する**（2026-08-30、/design時の本人指摘により確定。詳細レイアウトは `docs/03-design/screen-flow.md` のワイヤーフレーム参照）。

- 対応機能: F-01, F-02, F-04, F-19
- 意図・背景: 調整結果を見ながら画像を切り替えられるよう、常に主要な要素を同時に表示する。調整パネルは項目数が多くフルハイトでも余裕がないため、アクションバー分の高さを譲らない

## 4. 調整パネル（右）

4グループに分けてスクロール可能なパネルに表示する（Q-09, Q-14）。各項目はスライダー等＋現在値の等幅数値表示。「この画像の調整をリセット」ボタンで全項目を初期値に戻せる。

### 4.1 明るさ系

- 対応機能: F-01（明るさ・コントラスト）, F-21（トーンカーブ）
- 項目: 明るさ → コントラスト → トーンカーブ
- 【重要】当初あった「露出」「ハイライト」「シャドウ」は、RV-05により削除・トーンカーブに統合した。明暗の細かい調整は原則トーンカーブで行う想定。ただし本人からの指摘（prototype-notes.mdの「レビューしてほしい観点」）として、統合後に簡単な調整がしにくくなっていないかは`/design`実装後に改めて確認すること

### 4.2 色系

- 対応機能: F-01（彩度・色相・色温度）, F-11（Vibrance）, F-23（HSL個別調整）
- 項目: 彩度 → 自然な彩度（Vibrance） → 色相 → 色温度 → HSL個別調整
- 【重要】当初あった「デヘイズ」「カラーグレーディング」はRV-03・RV-05により削除

### 4.3 質感・効果系

- 対応機能: F-01（シャープネス・ビネット）, F-12（明瞭度）, F-09（全体ぼかし）, F-26（ノイズ除去）, F-07（プリセットフィルター）
- 項目: シャープネス → 明瞭度 → 全体ぼかし → ビネット → ノイズ除去 → プリセットフィルター（なし/モノクロ/セピア/ビンテージのワンクリック切替）

### 4.4 変形・仕上げ系（新設グループ、Q-14）

- 対応機能: F-13（反転）, F-14（回転）, F-15（トリミング）, F-16（フレーム）, F-18（自動補正）
- 項目: 反転（左右/上下の各オン・オフボタン） → 回転（90度単位、±90°ボタン） → トリミング（「開始」で枠を表示、ドラッグで移動・角のハンドルでリサイズ、「確定」/「解除」） → フレーム（縁取りの太さ＋色スウォッチ） → 自動補正（4.5参照）
- 当初あった「ウォーターマーク」はRV-04により削除

### 4.5 自動補正（F-18、RV-07で4パターンに拡張）

ワンクリックのボタンを4つ用意し、それぞれ異なるアルゴリズムで明るさ・コントラスト等の調整値を自動算出して適用する。

| # | 名称 | 処理内容 |
|---|------|---------|
| ① | オートコントラスト | 画像のヒストグラムを解析し、上下1%程度の外れ値を無視して、実際に使われている明暗レンジを0〜255いっぱいに引き伸ばす（レベル補正） |
| ② | オートホワイトバランス | グレーワールド仮説（画像全体の色は平均すると無彩色になるはず、という仮定）に基づき、R/G/Bチャンネルの平均値の偏りから色かぶりを検出し、色温度を補正する |
| ③ | 適応的トーン補正 | 局所的なコントラストを強調する（CLAHE: Contrast Limited Adaptive Histogram Equalizationに近い考え方）。既存の「明瞭度」の自動版に近い |
| ④ | おまかせ強調（Vivid） | 個々の画像を解析せず、彩度・自然な彩度・コントラストをやや強めにかけた「映える」固定の仕上げを適用する |

- ①〜③は画像ごとに実際の画素値を解析して補正量を決める。④のみ画像非依存の固定プリセット
- 具体的な数式・閾値（外れ値カット率、局所処理のウィンドウサイズ等）は `/design` で決定する。プロトタイプでの近似実装は `prototype/index.html` の `analyzeImagePixels` / 各モードの算出ロジックを参考にしてよいが、そのまま流用せず正しい画像処理ライブラリ（Pillow/numpy）で実装し直すこと

### 4.6 トーンカーブ（F-21、RV-02・RV-06で仕様拡張）

- 曲線上のクリックで新しい点を追加、ドラッグで自由な位置（X・Y両方向）に移動、ダブルクリックで点を削除できる本格的なカーブエディタとする（RV-02のA+B+C回答）
- 「全体／R／G／B」のチャンネルを切り替えて、チャンネルごとに別々のカーブを持てる
- 点と点の間は直線ではなく、なめらかなスプライン曲線（Catmull-Rom等）で結ぶこと。折れ線での接続は不可（RV-06）
- ハイライト・シャドウの調整はこの機能に統合されており、独立したスライダーは持たない
- 実際の画像への適用は、各チャンネルのカーブをLUT（ルックアップテーブル、0〜255の入力に対する出力の対応表）として計算し、numpyで一括変換する方式を想定。具体的な補間方法（線形/Catmull-Rom/その他）は`/design`で決定する

## 5. Before/After比較（F-19）

- プレビュー上部の「Before/After比較」ボタンでON/OFFを切り替え、ONの間はスライダーで比較位置を左右にドラッグできる（左側=加工前、右側=加工後）

## 6. リサイズ（F-04）

- プリセットボタン（FHD 1920×1080 / 4K 3840×2160 / 元のサイズ）と、幅・高さの数値入力の両方を提供する
- 「比率固定」トグルがON（デフォルト）のとき、幅を変更すると高さは元画像の縦横比から自動計算される（逆も同様）
- クロップ／レターボックスなど、指定サイズと元画像比率が一致しない場合の具体的な扱いは `/design` で決定する

## 7. 一括適用と出力設定（下部バー）

- 対応機能: F-03, F-05, F-20, F-27, F-28
- 「この設定を対象フォルダの全画像に一括適用」ボタン（現像=アンバーで塗りつぶし、最も目立つ主要アクション）。押すと進捗を表示し、完了後は結果（成功件数、保存先）をメッセージで表示する
- 元の対象フォルダ（`C:\壁紙\backup\ver3`）は変更せず、加工結果は別の新規フォルダに保存する（F-05）
- 出力形式（jpg/png/webp）、バッチリネーム（プレフィックス・開始番号・桁数、ファイル名例をリアルタイム表示）、AIによる高画質化（F-28）の有効化トグルを、一括適用ボタンの近くにまとめて配置する

## 8. デスクトップ壁紙に設定（下部バー）

- 対応機能: F-06
- 「この画像をデスクトップ壁紙に設定」ボタン（定着=インディゴの縁取りのみ、一括適用ボタンとは異なる役割であることを色で示す）
- 実行前に対象画像名を含む確認ダイアログを表示してから確定する（誤操作防止）
- Windowsのデスクトップ壁紙設定機能を使う（具体的なAPIは `/design` で決定）

## 9. スライドショー（新設、F-10・US-15）

- 対応機能: F-10
- 配置: 下部バーの「デスクトップ壁紙に設定（F-06）」ボタンのすぐ下に、間隔プルダウン＋ON/OFFトグルボタンの1行を配置する
- 項目: 切り替え間隔のプルダウン（1分／10分／30分／1時間／6時間／1日、デフォルト30分）＋ ON/OFFトグルボタン1つのみ。対象フォルダ（直近の一括適用（F-03）の出力先固定）と表示順（ランダム固定）は`questions.md`ラウンド5 Q-18・Q-20の回答により選択肢を出さない
- ONにすると、ボタンの見た目が「壁紙設定」と同系統ではなく、成功状態を示す緑（`--ok`）に変わる（一括適用=アンバー、壁紙設定=インディゴ、スライドショーON=緑、と3つのアクションが色でも区別できるようにする）
- 実現方式はWindows標準の「デスクトップの背景」スライドショー機能を使う想定（アプリはフォルダ・間隔を設定してON/OFFを切り替えるところまで。具体的なAPI・レジストリ操作は`/design`で決定）
- 間隔プルダウンは、スライドショーON中に変更した場合は即座に新しい間隔を反映する

- プロトタイプはブラウザ（HTML/CSS/JS）で作ったが、本実装の技術（言語・GUIフレームワーク）はこれに縛られない。`/design` で決定する

- リサイズ・トリミングのプレビュー表示（実際のピクセル再計算をしていない）は捨てる。本実装では実際に処理した結果を扱う
