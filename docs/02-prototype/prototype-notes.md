## デモ上の割り切り（本実装では変わりうる点）

- **シャープネス**: CSSでは本物のシャープ化ができないため、コントラストを僅かに強める近似表現にしている。実際のアルゴリズムは `/design` で決定する。
- **色温度**: 半透明オーバーレイによる簡易表現。
- **自然な彩度(Vibrance)・明瞭度(Clarity)**: CSSの`saturate`/`contrast`フィルターへの加算による近似。実際の画像処理アルゴリズムは既に`src/wallpaper_editor/image_ops.py`に実装があるため、本実装ではそちらを踏襲する。
- **HSL個別調整**: CSSには色域（色相帯）だけを選択的に処理する機能が無いため、選択中の色域にのみ簡易的に彩度/明度の全体フィルターをかける近似にしている。**本実装では実際に色相ごとのマスク処理が必要**（`/design`で技術検討）。
- **トーンカーブ**: 点は自由に追加・移動・削除できる本格仕様にしたが、実際に画像へピクセル単位で適用するのではなく、各チャンネルの点の平均的なズレを明るさ/コントラスト（全体チャンネル）や色味オーバーレイ（R/G/Bチャンネル）へ荒く変換して見た目に反映している近似表現。**本実装では実際のトーンカーブ（LUT）処理が必要**（`/design`で技術検討、実装コストが高い点に注意）。
- **ノイズ除去**: デモでは視覚的な効果を再現していない（UIの配置確認のみが目的）。
- **トリミング**: プレビュー上にドラッグ可能な枠を表示し、確定するとCSSの`clip-path`で見た目上クロップする。実際のピクセル切り出し計算は行っていない。
- **AIによる高画質化（超解像）**: チェックボックスのみのモック。実際に高画質化処理を行う技術（外部ライブラリ／モデル）は `/design` で選定が必要（`feature-list.md`のF-28備考を参照）。
- **リサイズ**: プレビュー画面上でのピクセル再計算は行っていない（プリセット・数値入力のUIのみ確認用）。クロップ／レターボックスの具体的な計算方法は `/design` で決定する。
- **一括適用・壁紙設定**: どちらも見た目だけのモック。実際の保存先フォルダ名・壁紙設定方法（Windows API等）は `/design` で決定する。
- **自動補正（4パターン）**: ①オートコントラスト・②オートホワイトバランス・③適応的トーン補正は、実際にこのサンプル画像のピクセルをブラウザのcanvasで解析（縮小サンプリングしたヒストグラム・RGB平均）して補正値を計算しているが、CSSフィルターへの変換は近似。④おまかせ強調（Vivid）は画像解析をせず固定の仕上がり値。実際のアルゴリズムの詳細（外れ値の閾値、CLAHE風処理の実装方法等）は`/design`で検討する。
- **スライドショー（F-10）**: ON/OFFボタンとプルダウンの見た目・擬似ログのみで、実際にはWindowsのスライドショー設定は変更されない。本実装での実現方法（レジストリ操作か`IDesktopWallpaper` COMインターフェースか等）は`/design`で技術検討する。

## レビューしてほしい観点（例）

- トーンカーブの操作感（点の追加・移動・ダブルクリック削除、チャンネル切替）は分かりやすいか。本格的すぎて逆に使いにくくないか
- ハイライト/シャドウの調整をトーンカーブに統合したことで、逆に「明るい部分だけ・暗い部分だけ」の簡単な調整がしにくくなっていないか
- 調整項目・スライダーの並びやグループ分け（明るさ系/色系/質感・効果系/変形・仕上げ系）は分かりやすいか
- 「上級」タグの付け方・扱いに違和感はないか
- Before/After比較の出し方（ボタン＋スライダー）は使いやすいか
- 出力形式・バッチリネーム・AI高画質化を「一括適用ボタンの近く」に置いた配置は適切か
- 一括適用・壁紙設定ボタンの位置や文言に違和感はないか
- 他にも重複・不要と感じる項目があれば教えてほしい
- スライドショー（F-10）の置き場所（壁紙設定ボタンの下）や、間隔プルダウン＋ON/OFFボタンだけのシンプルな構成で十分か（対象フォルダ・順序は選択肢を出さず固定にしている点も含めて）
