# 壁紙加工ツール（Wallpaper Editor）

フォルダ内の壁紙画像にまとめて色調補正をかけ、そのまま Windows のデスクトップ壁紙やスライドショーに設定できるデスクトップアプリです。
1枚の画像で調整しながらプレビューし、決まった設定をフォルダ内の全画像に一括で適用します。

![スクリーンショット](docs/images/screenshot.png)

## 主な機能

| 分類 | 機能 |
|---|---|
| 明るさ系 | 明るさ・コントラスト・ハイライト / シャドウ・**トーンカーブ**（点を追加してドラッグ、RGB チャンネル別） |
| 色系 | 彩度・自然な彩度（Vibrance）・色相・色温度・**HSL 個別調整**（色域ごとの彩度 / 明度） |
| 質感 | シャープネス・明瞭度・ビネット・ぼかし・ノイズ除去・フレーム（縁取り） |
| 変形 | 左右 / 上下反転・90度回転・トリミング・リサイズ（アスペクト比を保ったクロップ、高画質アップスケール） |
| 自動補正 | オートコントラスト・自動ホワイトバランス・適応トーン・ビビッド（ワンクリック） |
| プリセット | モノクロ・セピア・ビンテージ |
| 一括処理 | フォルダ内の全画像へ適用、出力形式（jpg / png / webp）の選択、連番リネーム。**元画像は変更しない**（別フォルダに出力） |
| 壁紙 | 選んだ1枚をデスクトップ壁紙に設定／出力フォルダ全体を**ランダム順スライドショー**に設定（間隔を選択） |
| その他 | Before / After 比較表示・調整値の保存 |

## 技術スタック

- **Python 3.12** / **Tkinter**（GUI）
- **Pillow** + **NumPy**（画像処理。トーンカーブは Catmull-Rom スプラインで LUT を生成）
- **ctypes** で Windows API を直接呼び出し
  - 壁紙の設定: `SystemParametersInfoW`
  - スライドショー: `IDesktopWallpaper` COM インターフェース（pywin32 などの追加ライブラリなしで vtable を直接呼び出し）
- **pytest**（ユニットテスト 67 件。Windows API はモックして検証）

## なぜこう作ったか（設計判断）

このツールは **「元の画像を絶対に失わない」** ことと、**「追加のインストールなしで、Windows の標準機能をそのまま使う」** ことを軸に設計しました。
判断の経緯は `docs/` の各工程の記録（質問シート・実装メモ）に残しています。

### 1. 元画像には一切書き込まない（非破壊）

- **課題**: 開発を始めてから対象フォルダを調べたところ、「未加工のバックアップ」だと思っていた画像が、実は過去に別の作業で彩度を上げた**加工済みの画像**だったと分かりました。加工を上書きで保存し続けた結果、本当のオリジナルがどれか分からなくなっていたのです（経緯は [要件定義の質問シート Q-10〜Q-12](docs/01-requirements/questions.md)）。
- **判断**: 一括加工の結果は、毎回 `<元フォルダ名>_edited_<日時>` という**新しいフォルダ**に保存します。元のフォルダには読み込み以外で触れません。画像処理の関数も、受け取った画像を変更せずに新しい画像を返します。
- **理由**: 加工は何度でもやり直せますが、上書きされたオリジナルは二度と戻りません。
- **補足**: 100枚以上を一度に処理するので、1枚が壊れたファイルでも止まらずに残りを処理し、最後に失敗した件数を知らせます。

### 2. 画像処理と画面を分けて、画面以外をすべてテストする

- **判断**: `image_ops.py`（画像の変換）・`auto_correct.py`（自動補正）・`batch.py`（一括処理）・`wallpaper*.py`（Windows との連携）・`gui.py`（画面）に分けました。画面以外のモジュールは Tkinter に依存しません。
- **理由**: 画面を操作するテストは自動化が難しく壊れやすいので、ロジックを画面から切り離し、pytest で直接確かめられるようにしました（テスト67件）。テストは画面のない Linux（Docker）でも実行できます。画面の動作は、[受け入れテストのシナリオ](docs/05-acceptance/acceptance-scenarios.md)に沿って人が確認します。

### 3. 自動補正は「画像」ではなく「スライダーの値」を返す

- **判断**: 自動補正（オートコントラストなど4種類）は、補正済みの画像を返すのではなく、明るさ・コントラストなどの**調整値**を計算して、画面のスライダーに反映します。
- **理由**: 自動補正は「出発点」にすぎず、利用者はそこから好みに合わせて微調整したいはずです。値として返せば、そのままスライダーで続きを調整できます。
- **補足**: 自動補正は「画像を解析して値を出す」処理で、ほかの加工（値を受け取って画像に適用する）とは向きが逆です。テストの観点も違うため、独立したモジュールにしています。

### 4. 加工の順番を固定する

- **判断**: 反転・回転 → トリミング → プリセット → 色 → トーンカーブ → 明るさ・コントラスト → 質感 → ビネット → フレーム → リサイズ、の順に必ず適用します。
- **理由**:
  - 向きを最初に直すと、以降の処理（トリミング範囲など）を見た目どおりの向きで扱えます。
  - フレーム（縁取り）を最後のほうに置くと、ビネットや色調整の影響を受けません。
  - リサイズを最後に置くと、縁取りを含めた最終サイズがぴったり指定どおりになります。
- 詳細は [API 仕様](docs/03-design/api-spec.md) にあります。

### 5. トリミング範囲は「割合」で覚える

- **課題**: 調整はプレビュー用に縮小した画像で行いますが、一括処理では元の大きさの画像に適用します。ピクセル座標で覚えると、画像ごとにずれてしまいます。
- **判断**: トリミング範囲を、画像の幅・高さに対する 0.0〜1.0 の割合で保存します。
- **理由**: 割合で覚えておけば、どの大きさの画像にも同じ見た目の範囲で適用できます。

### 6. Windows の機能は ctypes で直接呼ぶ（追加ライブラリなし）

- **課題**: スライドショーを設定する方法として、レジストリを直接書き換える方式も考えました。しかし、実際の状態は公開されていない形式のファイル（`slideshow.ini` など）にも依存していて、確実に動かせません。一方、Windows の公式の手段である `IDesktopWallpaper` COM インターフェースを使うには、ふつうは `pywin32` や `comtypes` といった追加ライブラリが必要です。
- **判断**: Windows の公式 API（`IDesktopWallpaper`）を使い、Python 標準の `ctypes` で COM の関数テーブル（vtable）を直接呼び出す方式で実装しました。単体の壁紙設定も `SystemParametersInfoW` を `ctypes` で呼んでいます。
- **理由**: 追加のインストールなしで、Windows の設定画面から切り替えたときと同じ公式の仕組みで動かせます。
- **安全策**: すべての呼び出し結果（HRESULT）を検査し、失敗したら例外にして画面に知らせます。うまくいかなかったのに何も表示されない、ということが起きないようにしています。
- **検証の状況**: 自動テストでは COM 部分を模擬オブジェクトに置き換え、呼び出しの引数と順番を確かめています。実際の Windows 11 でも、COM オブジェクトの作成と状態（有効か・切り替え間隔）の読み取りが正しく動くことを確認しました。スライドショーの ON / OFF の切り替えは、[受け入れテスト AT-31〜33](docs/05-acceptance/acceptance-scenarios.md) で手動確認する項目としています。

### 7. 「AI で高画質化」は、AI モデルを使わずにできる範囲で

- **課題**: 本格的な AI 超解像（Real-ESRGAN など）には、重いライブラリと数十〜百 MB を超える学習済みモデルが必要です。ほかの27機能と比べて、規模がまったく違いました。
- **判断**: Pillow だけで実現できる最高品質の拡大（弱いノイズ低減 → Lanczos 補間で拡大 → アンシャープマスクで輪郭を補正）にしました。画面にも「AIモデルは使用しません」と明記しています（[設計の質問シート Q-01](docs/03-design/questions.md)）。
- **理由**: 実行に必要なライブラリを Pillow と NumPy の2つに保ち、どの PC でもすぐに動くようにするためです。機能の名前で実際以上のことができるように見せないことも重視しました。

### 8. 保存する設定は「調整値」だけにする

- **判断**: 次回起動時に復元するのは、画像の見た目を決める調整値（明るさ・色・トーンカーブなど）だけです。出力形式・ファイル名の規則・スライドショーの間隔は、保存しません。
- **理由**: これらは「画像をどう加工するか」ではなく、「一括処理をどう実行するか」の設定で、性質が違うためです。混ぜると、調整値のデータ構造（`AdjustmentSettings`）が本来の役割以外のものまで抱えることになります。
- **引き換えにしたこと**: スライドショーの間隔は、次回起動時に既定値（30分）に戻ります。ON / OFF の状態自体は Windows から読み取って復元するので、影響は小さいと判断しました。

### 9. GUI は Tkinter にして、凝った操作は割り切る

- **判断**: GUI には Python 標準ライブラリの Tkinter を使いました。追加のインストールが要りません。
- **引き換えにしたこと**: HTML のプロトタイプで合意した操作のうち、Tkinter で作ると手間の大きいものは簡略化しました。
  - Before / After 比較は、スライダーで境目を動かす方式ではなく、左右半分ずつの固定表示にしました。
  - トリミングは、角をつかんで大きさを変える方式ではなく、ドラッグで範囲を描き直す方式にしました。
- 簡略化したものは、すべて理由とともに[実装メモ](docs/04-implementation/impl-notes.md)に記録しています。

## セットアップ（Windows 10 / 11）

1. [Python 3.10 以上](https://www.python.org/downloads/)をインストール（「Add python.exe to PATH」にチェック）
2. このリポジトリをダウンロード（`git clone` または ZIP）
3. **`setup.bat` をダブルクリック**
   仮想環境の作成 → ライブラリのインストール → テストの実行 → デスクトップにショートカット作成、まで自動で行います。

起動はデスクトップの「壁紙加工ツール」、または `run_app.bat` から。

初回は同梱の [`samples/`](samples/) フォルダ（デモ用に生成した画像）を開きます。
別のフォルダを最初に開きたい場合は、環境変数 `WALLPAPER_SOURCE_DIR` にパスを設定するか、画面左上の「対象フォルダを開く…」で選んでください。

### テストだけ実行する

```powershell
.venv\Scripts\python -m pytest tests -q
```

GUI と壁紙設定は Windows 専用ですが、テストは Docker（Linux）でも実行できます: `docker compose run --rm test`

## フォルダ構成

```
src/wallpaper_editor/
  image_ops.py            画像補正の各処理（調整・トーンカーブ・HSL・フィルタ・リサイズ）
  auto_correct.py         自動補正
  batch.py                フォルダ一括処理
  wallpaper.py            壁紙の設定（Windows API）
  wallpaper_slideshow.py  スライドショー（IDesktopWallpaper COM）
  settings.py             調整値の保存・読み込み（%APPDATA%\WallpaperEditor）
  gui.py                  Tkinter の画面
tests/                    pytest
samples/                  デモ用サンプル画像（tools/make_samples.py で生成）
prototype/                要件確認用の HTML モック
docs/                     開発工程ごとの成果物
```

## サンプル画像について

`samples/` と `prototype/assets/` の画像は [`tools/make_samples.py`](tools/make_samples.py) でプログラム生成したもので、第三者の著作物は含みません。
