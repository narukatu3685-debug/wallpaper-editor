# /acceptance-test — 受け入れテスト

## 目的

要件・レビュー指摘・設計・実装内容を踏まえ、**人間が手で検証できる受け入れテストシナリオ**を作る。AI が担当するのはシナリオ作成までであり、**合否判定・出荷可否の結論は AI が出さない。**

## 開始時に行うこと（ゲートチェック）

1. `/implement` が完了していること（`docs/00-status.md` の「実装・単体テスト」行が `完了`）を確認する。未完了なら着手せず伝えて停止する。
2. `docs/00-status.md` の「受け入れテスト」行を `進行中` に更新する。

## シナリオ作成

- `docs/05-acceptance/acceptance-scenarios.md` に、`user-stories.md` / `feature-list.md` の各項目、および `review-feedback.md` の指摘（RV-xx）に対応するシナリオを作る。
- 各行: シナリオID（AT-xx）／対応US・F／前提条件／手順／期待結果／判定欄（`[ ] 合格 / [ ] 不合格`、空欄のまま）。
- 末尾に出荷判定欄を用意する：全シナリオ合格か／出荷可否の判断／判定者／判定日／残課題・条件付き出荷の条件。**この欄はすべて空欄のまま**にする（AI は記入しない）。

## 完了時に行うこと

- `docs/00-status.md` の「受け入れテスト」行を、シナリオ作成が終わった時点で `人間承認・レビュー待ち` に更新する。出荷判定が人間により記入されたとユーザーから伝えられたら、その旨を確認したうえで `完了` へ更新する。
- `docs/audit.md` に追記する。
- 完了報告（`CLAUDE.md` のフォーマット）。次のアクションは「`docs/05-acceptance/acceptance-scenarios.md` を使って受け入れテストを実施し、出荷判定を記入してください」の一択。**「出荷可能です」のような結論は書かない。**

## 入出力

- 入力: 実装物（`docs/04-implementation/impl-notes.md` ほか実装一式）
- 出力: `docs/05-acceptance/acceptance-scenarios.md`
