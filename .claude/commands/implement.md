# /implement — 実装・単体テスト

## 目的

要件・詳細設計・UI/UX仕様の3点セットに基づき、テスト駆動開発（TDD）でソースコードを実装する。この工程は人間の承認なしで AI が自走してよいが、要件の範囲を超える判断が必要になったら `/requirements` に立ち返る。

## 開始時に行うこと（ゲートチェック）

1. 承認済みの要件定義、`docs/03-design/` の設計一式、`docs/02-prototype/ui-spec.md` が揃っていることを確認する。欠けていれば着手せず、不足している工程に戻るよう伝えて停止する。
2. `docs/00-status.md` の「実装・単体テスト」行を `進行中` に更新する。

## 進め方（TDD）

1. 対象の機能（`feature-list.md` の F-xx 単位を目安）ごとに、テストケース一覧を洗い出す（正常系・異常系・境界値・UI仕様由来のケースを含む）。表にまとめ、`docs/04-implementation/impl-notes.md` に記録する。
2. 各テストケースについて次を繰り返す。
   - 🔴 Red: テストコードを先に書く → 実行して失敗を確認する
   - 🟢 Green: 実装してテストを通す
   - 🔵 Refactor: リファクタリングし、テストが引き続き通ることを確認する
3. **テストが通らないとき、テストケースを弱めたり「通ったことにして」先に進んだりしない。** 失敗は失敗として正直に報告する。技術的に難しい場合は `docs/04-implementation/questions.md` に理由と代替案を書いて確認を求める。

## `impl-notes.md`

- 実装した内容の概要、主要なファイル一覧を記録する。
- **末尾に「UI/UX仕様（ui-spec.md）の反映状況」表を必ず含める**（指摘ID／内容／実装箇所／状態）。「未実装」が残る場合は理由を明記する。全件「実装済み」になっているか確認してから完了報告に進む。

## 完了時に行うこと

- `docs/00-status.md` の「実装・単体テスト」行を `完了` に更新する。
- `docs/audit.md` に追記する。
- 完了報告（`CLAUDE.md` のフォーマット）。次のアクションは「`/acceptance-test` に進めます」の一択。

## 入出力

- 入力: 承認済みの要件定義 ＋ 詳細設計 ＋ `docs/02-prototype/ui-spec.md`
- 出力: テストケースの洗い出し ＋ テストコード（先に作成）＋ ソースコード ＋ `docs/04-implementation/impl-notes.md`
